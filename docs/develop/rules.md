---
title: 插件规范
description: 发布插件前要对照的要求。
---

插件发布前，检查资源使用、数据存储、日志与生命周期。官方插件遵循相同规范。

## 少占内存

每个启用的插件是一个一直运行的程序。机器人主人可能装几十个插件，跑在小内存的机器上。

- **只导入用得到的包。** 标准库能做的不引入第三方库，HTTP 用 `net/http`。
- **不要内嵌大模型厂商的 SDK。** 用 [`sdk/llm`](../advanced/llm.md) 通过 Agent 调用。
- **启动时不做重活。** 包级变量和 `init` 函数里不加载大文件、不建连接，放到 `OnStart` 或第一次用到时再做。
- **内存里的缓存要有上限。** 大的数据放数据库或文件，不要整个读进内存。
- **数据库优先用 `sdk/sqlitedb`。** 它比 `sdk/gormdb` 少占约 1.5 MiB 内存。

## 数据

- 业务数据放[框架管理的数据库](../tutorial/storage.md)，更新失败时能自动恢复。
- 已发布的数据库迁移保持不变，结构变更通过追加迁移完成。
- 不要读写其他插件的文件或数据库。需要对方的数据就用[服务](../advanced/services.md)调用它。
- 用到外部数据库（MySQL 等）时，连接信息做成密钥类型的配置项。在 `plugin.yaml` 里加上 `prepare_effects: external`，告诉机器人主人这个插件的数据不在框架的保护范围内。

## 日志

- 用 `log/slog` 或 `c.Logger()`。
- **不要往标准输出写任何内容**（`fmt.Println`、`print`）。标准输出被框架占用，往里写会让插件出错。
- 日志用英文。
- 不记录密钥、token、完整的配置、带密码的连接地址。

## 文字

- 给用户看的文字放 `i18n/`，至少提供 `en-US.json`，见[多语言](../advanced/i18n.md)。
- 返回的 `error` 里的文字用英文。

## 启动和停止

- 连接、文件等资源在 `OnStart` 里打开，在 `OnStop` 里关闭。
- 后台协程在 `OnStop` 里结束。
- `New` 每次调用返回新的对象，不依赖包级变量。

## 调用

- 普通的 Handler 要在 30 秒内返回。需要更久时用[多轮对话](../tutorial/conversation.md)里的 `.Continue()`，或者[定时任务](../advanced/schedule.md)。
- **有副作用的操作失败后不要自动重试。** 超时不代表对方没执行，重试可能导致发两条消息、扣两次款。
- 调用其他插件的服务或大模型时，处理对方不存在的情况。

## 广播

- 广播可能丢失。需要确认对方收到时用服务。
- 订阅的 Handler 里不要做耗时的事。

## 纯 Go

优先不用 CGO。纯 Go 的插件可以直接打出所有平台的安装包。确实需要 CGO 时，你要为声明支持的每个平台提供真正能运行的安装包。

## 命名

准备公开发布的组件，ID 按类型加前缀：

| 类型 | 前缀 |
| --- | --- |
| 插件 | `alonabot-plugin-` |
| Adapter | `alonabot-adapter-` |
| Agent | `alonabot-agent-` |
| WebUI | `alonabot-webui-` |

## 发布前

```sh
alonabot check
go test ./...
alonabot test
```

三个都通过，再[打包发布](../advanced/publish.md)。上传对应平台的归档。
