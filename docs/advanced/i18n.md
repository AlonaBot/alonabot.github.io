---
title: 多语言
description: 让插件按用户的语言回复。
---

给用户看的文字不要直接写在代码里，放进 `i18n/` 目录的语言文件，插件就能按用户的语言回复。

## 写法

```json title="i18n/en-US.json"
{
  "messages": {
    "added": "Added: {text}",
    "empty": "Nothing to do.",
    "full": "Your list is full ({limit} items)."
  }
}
```

```json title="i18n/zh-CN.json"
{
  "messages": {
    "added": "已添加：{text}",
    "empty": "没有待办。",
    "full": "清单已满（{limit} 条）。"
  }
}
```

代码里用 `c.T` 取文字：

```go
func add(c *sdk.Context, text string) error {
	return c.Reply(c.T("added", "text", text))
}

func list(c *sdk.Context) error {
	return c.Reply(c.T("empty"))
}
```

```text
> /todo add 买牛奶
已添加：买牛奶
```

`c.T` 的第一个参数是键，后面成对写「占位符名, 值」：

```go
c.T("full", "limit", fmt.Sprint(limit))
```

占位符的值是字符串。

## 用哪种语言

框架按下面的顺序决定：

1. 用户在平台上设置的语言（平台提供时）。
2. 机器人主人设置的缺省语言，即 Core 设置里的 `default_locale`。
3. 英文 `en-US`。

某种语言的文件里没有这个键时，用英文的。所以 **`en-US.json` 必须有全部的键**，其他语言可以只翻译一部分。

## 构建时检查

`alonabot check` 和 `alonabot build` 会检查 `c.T` 的调用：

- 键在 `en-US.json` 里不存在：报错。
- 占位符名和文件里的对不上：报错。
- 其他语言文件里的占位符和英文的不一致，或者有英文里没有的键：报错。

所以键和占位符名要直接写成字符串，不要拼接。键是运行时才算出来的话，检查不到。

## 语言文件里的其他内容

`messages` 之外，同一个文件里还可以翻译这些：

```json title="i18n/zh-CN.json"
{
  "messages": {
    "added": "已添加：{text}"
  },
  "commands": {
    "todo add": { "description": "添加一条待办" }
  },
  "config": {
    "limit": { "description": "每人最多几条", "hint": "超过后不能再添加" }
  },
  "pages": {
    "/page": "待办"
  }
}
```

| 节点 | 翻译什么 | 英文原文写在哪 |
| --- | --- | --- |
| `messages` | 回复用户的文字 | `en-US.json` |
| `commands` | 命令列表里的说明 | 代码里的 `.Description(...)` |
| `config` | 配置表单里的标题和说明 | `config_schema.json` |
| `pages` | 插件页面的标题 | 代码里的 `.Page(...)` |

## 后台任务里

没有 `c` 的地方（后台协程、HTTP 回调）用 `sdk.T`，按机器人的缺省语言取：

```go
text := sdk.T(ctx, "added", "text", item)
```

## 什么用英文，什么要翻译

| 内容 | 语言 |
| --- | --- |
| 回复给用户的文字 | 按用户语言，放 `i18n/` |
| 日志 | 英文 |
| 返回的 `error` 里的文字 | 英文 |
| 代码里的命令说明、配置说明、页面标题 | 英文，翻译放 `i18n/` |

日志和错误是给开发者和机器人主人排查问题用的，统一用英文方便搜索。
