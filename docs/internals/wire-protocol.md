---
title: 通信协议
description: Core 和组件进程之间怎么通信。
---

用 Go SDK 写组件不需要了解这一页。想用其他语言实现组件，或者调试通信问题时可以参考。

## 连接

Core 启动组件进程后，两者之间建立一条连接，有两种方式：

| 方式 | 说明 |
| --- | --- |
| TCP（缺省） | Core 在本机的一个随机端口上监听，组件连接过来 |
| 标准输入输出 | 组件的 stdin 和 stdout 用作通信通道 |

因为有第二种方式，**组件不能往 stdout 写任何其他内容**，日志要写到 stderr。SDK 的日志已经这样处理了。

每个组件进程启动时会得到一个随机的凭证，连接后第一件事是出示它。Core 验证通过才会发送配置等内容。

## 帧

连接上传输的是一个个「帧」：

```text
┌──────────────┬─────────────────────┐
│ 长度（4 字节） │ 内容（Protobuf 编码）  │
└──────────────┴─────────────────────┘
```

长度是大端的无符号整数，不包括自己这 4 个字节。一帧最大 4 MiB。收到长度为 0、超过上限或无法解码的帧时，连接直接断开。

## 帧的种类

| 种类 | 方向 | 用途 |
| --- | --- | --- |
| HELLO / HELLO_ACK | 组件 → Core / Core → 组件 | 握手，确认协议版本 |
| REGISTER | 组件 → Core | 组件报告自己登记了哪些命令、事件、服务 |
| PREPARED | Core → 组件 | Core 接受了登记 |
| ACTIVATE / ACTIVATED | Core → 组件 / 组件 → Core | 开始工作 |
| REQUEST / RESPONSE | 双向 | 一次调用和它的结果 |
| CANCEL | 双向 | 取消一次还没结束的调用 |
| EVENT | 双向 | 不需要回复的通知 |
| STOPPING | Core → 组件 | 要求组件停止 |
| HEARTBEAT | 双向 | 确认对方还活着 |
| SESSION_ERROR | 双向 | 出现无法继续的错误 |

## 调用

Core 调用插件的 Handler、插件调用 Core 发消息，用的都是 REQUEST 和 RESPONSE：

- 每个 REQUEST 有一个编号，RESPONSE 带着同样的编号回来。所以多个调用可以同时进行，回来的顺序不用和发出的顺序一样。
- 每个 REQUEST 带着截止时间。在一次调用里发起的子调用，截止时间不能晚于父调用。
- 同时进行的调用数量和总大小有上限。超过时新的调用立刻失败，不排队等待。

## 取消和超时

取消是「请求对方停下来」，对方可能已经做完了。同样，超时只说明没等到结果。

所以协议不会自动重试有副作用的调用（比如发消息）。SDK 把超时和取消作为错误交给你的代码，由你决定怎么办。

## 版本

协议有自己的版本号，和框架的版本号分开。目前是 1.0。

握手时双方交换版本号。主版本不同则拒绝连接；次版本不同时用较低的那个。所以用旧 SDK 编译的插件可以在新的 Core 上运行，只要主版本相同。
