WebUI provides buttons for these operations. This chapter covers CLI usage for servers and scripts.

## Preparation

Run commands from Core's startup directory with the same data directory. Add `--data-dir <data-directory>` to select another directory.

Management commands connect to the running Core and read credentials from the same data directory. To supply different credentials:

```fish
set -gx ALONABOT_ADMIN_TOKEN 'your-management-token'
```

Alternatively, save the token to a file and add `--token-file <file>`.

## Plugins

```sh
# Install from GitHub
alonabot install --source yourname/alonabot-plugin-todo --yes

# Install a downloaded archive
alonabot install ./alonabot-plugin-todo-0.3.0-linux-amd64.tar.gz --yes

# List installed components
alonabot list

# Disable and enable
alonabot disable alonabot-plugin-todo
alonabot enable alonabot-plugin-todo

# Update to the latest version
alonabot update alonabot-plugin-todo

# Restore a retained generation, including its data
alonabot rollback alonabot-plugin-todo <generation-id>

# Uninstall and retain data
alonabot uninstall alonabot-plugin-todo --yes

# Uninstall and delete data
alonabot uninstall alonabot-plugin-todo --purge --yes
```

Find retained generation IDs in the WebUI component details. Run without `--yes` first to inspect the affected data, then add `--yes` to proceed. Rollback discards data written after the target generation.

:::caution Install trusted plugins
Plugins are programs with Core's system permissions. They can read and write anything accessible to Core on the machine.
:::

## Develop with a third-party Adapter

Install a third-party Adapter from its source repository after verifying the source.

For a development plugin in `./my-plugin`, start a development Core in terminal one:

```sh
alonabot run ./my-plugin --data-dir ./qq-dev-data --log-level debug
```

Open terminal two in the same working directory. Set the token generated by this Core, install the Adapter, and add an account. Replace the example repository and component ID with actual values. Prepare `qq-account.json` according to that Adapter's account configuration.

```fish
set -gx ALONABOT_ADMIN_TOKEN 'token-from-this-core'

# Inspect the initial trust prompt, then confirm installation
alonabot install --source author/alonabot-adapter-qq --data-dir ./qq-dev-data
alonabot install --source author/alonabot-adapter-qq --data-dir ./qq-dev-data --yes

# Creating an account binds the component, enables the Adapter, and starts the account
alonabot adapter instance create alonabot-adapter-qq qq-main --config ./qq-account.json --data-dir ./qq-dev-data
```

Send a QQ message to test the plugin. Saving code in `./my-plugin` recompiles and restarts it; the installed Adapter keeps its installed version. For Adapter hot development, see [Debug third-party source](../develop/adapter.md#debug-third-party-source).

## Bot administrators

```sh
alonabot admin list
alonabot admin add telegram:123456789
alonabot admin remove telegram:123456789
```

## Platform accounts

```sh
# Add: platform component ID, account name, configuration file
alonabot adapter instance create alonabot-adapter-telegram main --config tg.json

alonabot adapter instance stop main
alonabot adapter instance start main
alonabot adapter instance delete main
```

`tg.json` contains account settings, such as `{"token": "..."}`.

## Logs

```sh
# Recent logs
alonabot logs

# Follow new logs
alonabot logs --follow

# Errors from one plugin
alonabot logs --source alonabot-plugin-todo --level error

# Logs for a specific date
alonabot logs --date 2026-11-18
```

Log files are stored under `logs/` in the data directory, one file per day.

Temporarily increase a plugin's log verbosity:

```sh
alonabot log-level alonabot-plugin-todo debug
```

## Backup and recovery

Stop Core before a backup, then copy the whole data directory. Copying only `state.sqlite` is not enough: it does not contain plugin data.

To restore, stop Core, replace the whole data directory with the backup, then start Core. Data written after the backup is lost.

External databases a plugin connects to, and files outside the data directory, are not included; back them up as that plugin documents.

## Diagnostics

Export recent logs, settings, and component information:

```sh
alonabot diagnose --data-dir <data-directory> -o diagnose.zip
```

Secrets and tokens are redacted automatically. Review the archive before sharing: logs may contain chat messages.

This command also works when Core is stopped.
