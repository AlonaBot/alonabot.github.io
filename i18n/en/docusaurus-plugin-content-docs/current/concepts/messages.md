Plugins receive events after Core normalizes them, independent of the platform. Exact definitions are in [MESSAGE-MODEL.md](https://github.com/AlonaBot/AlonaBot/blob/main/spec/MESSAGE-MODEL.md).

## Event, Actor and Target

| Type | Meaning |
| --- | --- |
| **Event** | One inbound event. Core assigns `event_id` during normalization; `event_type` tells the kind; platform fields exist only for that source |
| **Actor** | The user who triggered it. `permissions` is the set of permission names computed by Core; adapters supply only the platform permissions for this chat |
| **Target** | Where a message goes: adapter, instance, account, chat and optional thread. The default Target comes only from the actual inbound event |

IDs in public JSON are strings and times are UTC Unix milliseconds. Missing fields stay missing; there are no made-up users or zero IDs.

## Common event types

| `event_type` | Meaning |
| --- | --- |
| `message.created` | A new message, with `chain` and `to_me` (true for private chats, replies to the bot or mentions) |
| `message.edited` / `message.deleted` | A message was edited or deleted; not sent if the platform has no such notice |
| `button.clicked` | A button was clicked; the Actor is whoever clicked |
| `member.joined` / `member.left` | Members joining or leaving |
| `reaction.added` | A reaction |
| `scheduled` | A scheduled job fired |
| `bot.online` / `bot.offline` | Generated by Core when an adapter instance goes up or down |

## Permission names

Commands are admitted by permission name:

- `user`: a user with a trusted Actor. Commands and text matches require it by default.
- `admin`: a bot admin configured in Core, identified by adapter instance and external user ID.
- `chat_admin` and adapter-declared platform permissions (for example `onebot11.group_owner`): valid only within that chat, never granting Core admin rights.

Core's global deny rules always apply, and dynamic policies are rechecked before every dispatch.
